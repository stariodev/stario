# Audit and improvement plan (November 2026)

Scope: the whole repository at `58bcd83` (5.4.0): the Cython protocol and
exchange, the Python HTTP layer, markup and Datastar, telemetry, filesystem,
relay, cookies, forms, the test client and the test suite. The goal was to
find bugs, needless complexity and dead code, and to make the day-to-day
path (an HTML page or an SSE patch per request) as cheap as it can be while
the server keeps handling a large number of connections.

Every claim below is marked **[verified]** when it was reproduced here with
a script or test, or **[review]** when it comes from a code read that was
not independently reproduced. Numbers are from this container (4 vCPU,
Python 3.14.6, uvloop 0.23, nghttp2 1.59, Brotli 1.1.0, zstd 1.5.5) and
only compare against each other.

writes, so it measures framework cost without sockets or a load generator.

| `validate_post` | 7.1 | 23-byte JSON body via `c.req.body()` |

| `page_html_zstd` | 222.8 | same, compressed on the wire |
| `page_html_br` | 277.3 | |

| `sse_patch_signals_identity` | 7.6 | per `patch_signals` of a 2-key dict |

Other baselines:

- `benchmarks/html/compare.py`: `@baked` 41.5 µs, Jinja2 100 µs, naive
  Stario tree 259 µs per 50-row page. Building the tree is 77% of the naive
  cost (137 µs build, 40 µs render for 263 elements). **[verified]**
- Real sockets, 64 keep-alive connections, Python load generator (client
  bound): `/plaintext` 49k req/s, `/page` 4.0k req/s identity, 3.7k zstd.
- Idle memory: 2000 idle keep-alive connections add 9.8 KiB each (RSS).
  `Connections.sweep` over 10k idle connections: 3.6 ms per second.
  **[verified]**
- Test suite: 1504 passed, 1 skipped, 1 deselected in 24 s. Ruff and
  pyrefly clean. One test fails on a machine whose distro Brotli is 1.1.0
  (`test_linked_brotli_decoder_rejects_invalid_block_switch`); CI builds
  1.2.1 so it passes there.

What this says: the compiled protocol is not where day-to-day time goes.
For a page request the ratio is roughly 2 µs protocol, 20 µs telemetry
(when it is on), 220 µs markup. Those two are the levers.

## 2. Bugs

Ranked by impact. Each item names the file and line, what happens, and the fix.

### B1. A plain 4-tuple child renders as trusted markup (escaping bypass) [verified]

`src/stario/markup/render.py:29-70` dispatches on `type(node) is tuple` and
emits items 0, 1 and 3 verbatim; `src/stario/markup/tag.py:200-202` accepts any
non-mapping as a child. A database row is a tuple:

```python
row = ("<img src=x onerror=alert(1)>", " onclick=evil", "abc", "")
render(h.Li(row))   # <li><img src=x onerror=alert(1)> onclick=evil>abc</li>
render(h.Li(*row))  # escaped, as expected
```

A 3-tuple raises; only the 4-tuple shape is mistaken for an element. Fix:
make the element node its own type (`class Element(tuple): __slots__ = ()`
built in `Tag.__call__`) and dispatch on `type(node) is Element` in
`_render` and `baked._flatten_node_into_segments`; a plain tuple then hits
the existing "cannot render" error. Measured cost +45 ns per element.

### B2. Message-less exceptions export as `status: "ok"` [verified]

`invoke.py:113` and `spans.py:348` call `span.fail(str(exc))`; for
`CancelledError()`, `KeyError()`, `ValueError()` that is `""`.
`telemetry/json.py:33,39` and `testing/tracer.py:41` test truthiness, so the
span is exported as a clean success with no `error` key. TTY uses
`span.failed` (`error is not None`) and shows the failure. A crash with an
argument-less exception is invisible in production logs. Fix: compare with
`is not None` in the two sinks and use `str(exc) or type(exc).__name__` at
the two `fail` call sites; add a test.

### B3. `set_cookie(expires=<str>)` rejects every valid HTTP-date [verified]

`src/stario/cookies.py:129-134` raises when the string contains `,`; every
IMF-fixdate (`Wed, 21 Oct 2015 07:28:00 GMT`, the format the `int` and
`datetime` branches themselves emit) contains one. The documented `str`
form is unusable. Fix: drop the comma check (CR/LF injection is already
caught by `headers.add`), or drop `str` support. No test covers the path.

### B4. `h.Script` / `h.Style` entity-escape their text [verified]

`render(h.Script("if (a<b && c) go()"))` gives
`<script>if (a&lt;b &amp;&amp; c) go()</script>`. Script and style are
raw-text elements; the browser does not decode entities there, so the
JS/CSS is silently broken. Not exploitable, but a trap that
`tests/test_markup.py:945-950` currently pins as correct. Fix: a
`raw_text=True` tag mode that rejects plain `str` children with an error
pointing at `SafeString` (never emit unescaped text by default).

### B5. Datastar `data.on("myEvent")` and friends silently change the name [verified]

`attributes.py:290` (`data.on`) and its key builder in `format.py` emit
`data-on:my-event` for `data.on("myEvent", ...)` without a `__case.camel`
modifier, so the listener is for `my-event`. `data.class_("myClass")` emits
`data-class:myClass`, which the HTML parser lowercases. `match_media`
already handles this via `signal_attr_key` (`format.py:413-456`); apply the
same rule to `on`, `attr`, `class_`, `style`, `bind`: emit the case
modifier when the name has uppercase, or reject.

### B6. `SSE.patch_elements(str)` sends raw HTML [verified in code]

`sse.py:148-153`: `bytes` and `str` go on the wire unescaped while an
element tree is rendered with escaping. Consistent with `w.html(str)`, but
`patch_elements(user_text)` injects. Accept `bytes | SafeString | HtmlElement`
and make the `str` case an error, or document loudly.

### B7. `Files` cache eviction can raise `KeyError` with `STARIO_THREADS>1` [verified in code]

`filesystem.py:1098-1101`: two loops serving the same changed file both see
a stale entry and both `del self._cache[path]`; the second raises and the
request is a 500. Single loop is safe (no `await` between the get and the
del). Fix: `self._cache.pop(path, None)`.

### B8. `Assets.load()` reads every small file twice and ignores the budget while reading [verified in code]

`filesystem.py:847-879`: every file at or below `max_file_size` is read into
`bodies` before `max_bytes` is applied, then every catalog entry is
fingerprinted from disk again. A tree of 2 GB of sub-MiB images peaks near
2 GB RSS at startup and reads 4 GB. Fix: apply the budget while walking and
re-verify only entries pinned by `href()` before `load()`.

### B9. HTTP/2 slow reader: unbounded backlog and O(backlog) compaction [verified superlinear]

`protocol.pyx:3490-3541` (`_h2_pending_extend`): when nghttp2 has sent a
prefix of the pending buffer, the next `write()` memmoves the whole unsent
tail to the front and shrinks the bytearray. With a slow client that is
one O(backlog) copy per 16 KiB DATA frame sent, and nothing but
`w.drain()` bounds the backlog. A handler writing 16000 × 1 KiB chunks under
a 16 KiB window spent 6.5× the time of the 8000-chunk run (31 ms vs 4.8 ms).
Fix: compact only when the sent prefix exceeds half the buffer (amortised
O(1)), and cap unsent bytes per stream (reset the stream or raise, like the
write-timeout path does for time) so a handler that never drains cannot grow
without bound.

### B10. Multi-range requests are answered 416 [review]

`filesystem.py:246-247` treats `,` in a Range as unsatisfiable. RFC 9110
§14.2 lets a server ignore multi-range (200 with the full body); 416 is
wrong. Return `None` for comma specs.

### B11. Multipart: empty-file parts bypass `max_files` [review]

`forms/read.py:147-160` counts kept files, and parts with an empty filename
are never kept, so each one allocates and closes a `SpooledTemporaryFile`
without counting. Bounded by `max_size`; CPU only. Count parts started.

### B12. Telemetry overflow and shutdown edges [review]

- `buffered.py:187-200`: when the queue is full, every dropped span writes
  and flushes stderr on the request thread, at exactly the moment the
  process is saturated. Rate-limit the message.
- `buffered.py:153-161`: `_running = False` is set before `thread.join()`;
  a span ending in that window is counted dropped although the drain after
  the join would have taken it.
- `tty.py:1430-1437` then `:1552`: `_stop` joins the render thread with a
  1 s timeout, then `flush()` takes `_write_lock`; a render thread stuck in
  a terminal write defeats the timeout and shutdown hangs.
- `spans.py:351` (`event`): `events` has no cap. The chat-room example records an
  event per relay message inside an SSE loop; a connection open for hours
  accumulates every event and exports one enormous line at the end. Cap
  events per span and record a `dropped_events` attribute.

### B13. HTTP/2 413 during a read is answered twice [suspected, verify]

`protocol.pyx:2959-2968`: when a stream exceeds the read limit while the
handler is already running, the protocol itself calls `ex.respond(b"", 413)`.
The handler's `body()` then raises `RequestBodyError(413)`, `invoke.py`
tries `w.text(...)`, which raises "already started", and the span records
a failure with a traceback for what is a normal 413. HTTP/1 does not
preempt. Reproduce with an H2 upload over the limit and check the span;
if confirmed, let the handler's exception path answer and have the protocol
only reset the stream when no handler is running.

### Also noted

`Relay` docstring (`relay.py:365-367`) says `_inbox_lock` is never held
during `Future.set_result`; `deliver()` → `_hand_off_locked()` does hold it.
Harmless, but the claim is false. `_dot_kind` in `path.pxi:239-249` is
fine; `canonical_path` allocates per 308 only.

## 3. Performance on the day-to-day path

### P1. Telemetry costs 22 µs per request with the default production tracer [verified]

`STARIO_TRACER` defaults to `auto`, which is JSON whenever stdout is not a
TTY (`telemetry/env.py:71-78`), so a containerised deployment traces every
request. Measured: `plaintext` 1.3 µs untraced, 24.6 µs with `JsonTracer`.

Where it goes, and what to do:

| Change | Evidence | Expected |
| --- | --- | --- |
| `RecordingSpan._mutate` (`spans.py:281-288`) is a `@contextmanager` generator entered on every `start/attr/attrs/rename/end`, about 7 times per request. Make `mutex` always a context manager (`nullcontext()` by default, the TTY lock when set) and write `with self.mutex:` | patched in place: 24.6 → 16.7 µs | −8 µs |
| `_span_id()` (`spans.py:21-63`) takes a process-global lock and does an `os.urandom(10)` syscall per id, two ids per request. Keep the state per thread and draw randomness in chunks | `uuid4` is 1.1 µs, this is 1.7 µs per id | −2 µs |
| `_serialize_span` (`json.py:22-71`) builds an intermediate dict and calls `str()` on 2–3 UUIDs on the writer thread, which competes for the GIL | writer serialising nothing: 16.7 → 14.0 µs | −2 µs |
| `finish_request_span` and `_start_exchange_inner` build an attrs dict and call `rename` for every request; `decode_request_path` runs only for the span | code read | −1 µs |

Target: `traced_json` ≤ 8 µs per request (from 24.4), measured with
`benchmarks/server/inproc.py traced_json`. Also document that spans are
single-thread owned (a `to_thread` worker calling `c.span.attr()` while
the handler ends the span races the writer on free-threaded builds).

### P2. Element construction is 77% of a page [verified]

`Tag.__call__` (`tag.py:113-239`) per element: an eager `self._repr()`
f-string used only in error paths; `isinstance(child, Mapping)` ABC dispatch
for every non-dict child (0.11 µs vs 0.03 for `type(child) is str`); per
attribute two `bake_slot_if_present` calls, `validate_attribute_key`,
`wire_scalar_attr_fragment` (3 Python calls + 2 C calls). All output stays
byte-identical with these changes, which the existing `TestBakedDifferential`
pins:

| Change | Measured (agent script, reproduced here) |
| --- | --- |
| Lazy `_repr`; test `str/tuple/SafeString/list` by `type` before the Mapping check; inline `type(v) is BakeSlot`; inline the `str` branch of the wire fragment | `Div('text')` 0.44 → 0.15 µs; `Div({'class':'card'})` 0.96 → 0.54; 3 attrs + 2 children 2.56 → 1.06; 100-row build 781 → 515 µs |
| `classes()` (`attributes.py:97-141`): check `type(token) is str` first; `lru_cache` the whole result for all-`str` argument tuples (Tailwind class lists repeat) | 0.70 → 0.46 µs; cached 0.10 |
| `styles()` (`attributes.py:18-96`): two generator `any()` scans per declaration → one regex and a cached key check | 1.80 → 0.65 µs |
| Drop the `lru_cache` on `escape_attribute_value` (`escape.py:21`): hit 69 ns vs 57 uncached; miss + evict 167 vs 108 for per-row `href`/`title` values. Keep the cache on `validate_attribute_key` | small |
| Render shape: fuse `tag_start + attrs + ">"` at build time, node = `(open, children, tail)`, childless element = `SafeString(open + tail)`; mirror in the baked flattener | render 132 → 85 µs per 100 rows |

The hand-rolled `escape_text` (3 × `in` + `replace`) was measured against a
regex gate, `str.translate` and markupsafe's C escape and is the fastest of
the four; keep it.

Target: `page_html_identity` ≤ 150 µs (from 219) with the pure-Python
changes; `benchmarks/html/compare.py` naive ≤ 170 µs (from 259), i.e. within
1.7× of Jinja2 instead of 2.6×.

Beyond that, the next step is a compiled tag builder: `Tag.__call__` and
`_render` are the only Python-level per-element work left, and a Cython
`Element` with a C walk would put the naive path near `@baked` (41 µs).
That is a larger change and should wait for the pure-Python round to land
and be measured.

### P3. SSE event cost [verified]

- `_sse_payload_lines` (`sse.py:158-162`) does two `replace` calls, a
  `split` and a `join` on every payload: four copies of the body. Stario
  markup never contains CR or LF, so gate it with
  `b"\n" in body or b"\r" in body`. A 20 KB patch: 19.5 → 1.9 µs.
- `expand_signal_paths` (`format.py:325`) splits every key via
  `check_signal_name` even when no key has a dot; it costs more than the
  JSON encoding. Gate on `"." in key`: `patch_signals` 7.6 → about 4 µs.

Target: `sse_patch_signals_identity` ≤ 4.5 µs; a 20 KB `patch_elements`
pays no more than the render plus one copy.

### P4. Load-path items [review, code verified]

- `Files.href()` (`filesystem.py:1037-1049` → `resolve()` at `584-612`)
  does about ten blocking syscalls on the event loop per call: the root is
  re-resolved, one `lstat` per component, a `resolve(strict=True)` and a
  `stat`. A page listing 200 uploads blocks the loop for 2000+ syscalls.
  Cache the resolved root and make `href()` a pure URL builder (GET 404s
  on a missing file, as `Route.href` does).
- `Relay.drop_subscription` (`relay.py:347-360`) rebuilds the bucket list
  under the registry lock: N subscribers of one pattern leaving at shutdown
  is O(N²) under one mutex. An insertion-ordered `dict[sub, None]` keeps
  delivery order and gives O(1) removal.
- Post-rollover upload writes (`forms/read.py:176-182`) hop to a thread per
  64–256 KiB chunk; batch to 1 MiB before hopping.
- `Connections.sweep` copies the set into a tuple and `isinstance`-checks
  every protocol each second (3.6 ms per 10k connections). A `cdef list`
  of `CHttpProtocol` walked in C removes both; only worth it past about
  50k connections.

## 4. Complexity and dead code

Removals that cost nothing in behaviour. Verified by grep over `src/`,
`tests/` and `examples/` unless marked.

- **Telemetry (~600 lines)**: `telemetry/sqlite.py` (414 lines) is
  deprecated for 6.0 and re-implements the writer loop; it is the only user
  of `formatters.serialize_json` and `_env.env_path`. `ProxySpan`
  (`spans.py:143-236`, 95 lines delegating 17 methods) exists for one swap
  in `bootstrap.py`. `TelemetryStats` / `stats()` has no production reader.
  `_terminal.style_text` / `styled` have no callers. `RecordingSpan.duration_ns`
  has no readers. Once SQLite goes, `_BufferedTracer` has one subclass and
  its three-level `_write_batches_safe → _write_batches → _write_batch`
  chain folds into `JsonTracer`.
- **TTY live footer (~500 of tty.py's 1678 lines)**: `_LiveRegion`,
  `_LiveEntry`, `_Passthrough` stdout/stderr proxying with pdb pause
  state, logging-handler retargeting, and the only reason spans carry a
  mutex at all (`span.mutex = self._lock`). `live=False` already prints
  finished roots like an access log. This is a product decision; it is also
  the single largest simplification available.
- **Compression**: `http/compression.py` keeps Python `Compressor`
  classes (`_Zstd`, `_Brotli`, `_Gzip`, `make_compressor`, `select`,
  `may_compress`) that only `filesystem.py` precompression uses, next to
  the Cython writer's native path. There are two Accept-Encoding parsers
  (`http/wire.py` Python LRU and `exchange.pyx:1310`) and two `merge_vary`
  implementations (`compression.py:112` and `headers.pxi:509`).
  `wire.decode_method` is used only by tests. Point `filesystem` at the
  `stario_cython.codecs` encoders directly and delete the Python classes
  and the duplicate parser.
- **Datastar**: `actions.py:157-424` holds six verbatim copies of the
  45-line `_fetch` signature (`get = partialmethod(_fetch, "get")`
  replaces ~270 lines). Thirteen "Datastar Pro only" helpers
  (`attributes.py:625-819`, `actions.py:426-477`, ~250 lines) for a paid
  plugin set: four tested, none used in examples; move to `datastar.pro`
  or drop. `format.case_modifier` and `types.AttributeDict` are dead.
  `markup.data` / `aria` / `prefixed` produce the same bytes as a flat dict
  and `data` collides with `stario.datastar.data`.
- **Filesystem**: three copies of the conditional-request pipeline
  (`Assets.__call__` cached branch, `Assets._stream_pinned`,
  `Files.__call__`), ~80 lines; one `_respond(...)` would make B7, B10 and
  the truncation path one fix each. `include_hidden=True` appears only in
  the changelog.
- **Cookies**: `parse_cookie_headers` is referenced only by tests; the
  runtime path is the Cython `ParsedCookies`.
- **Protocol**: `_task_kw_eager` / `_task_kw_lazy` are two dicts per
  connection that only depend on the loop; make them per-`Connections`.
  `write_headers` calls `self._transport.is_closing()` where the bound
  `_t_is_closing` exists. Both tiny.

## 5. Test suite

The suite is large and the protocol is tested at the wire level, which is
the right place. Three things weaken trust in it:

1. **Timing-driven tests dominate and have thin margins.** About 45
   sleep-driven timeout tests account for ~75% of the 24 s; `test_hardening.py`
   uses `_TIMEOUT=0.15` / `_WAIT=0.40` with a 50 ms sweep, and
   `test_h2_send_progress_keeps_stalled_stream_alive` relies on 0.1 s credit
   ticks under a 0.5 s write timeout. `test_hardening.py:1494-1504` already
   shows the alternative: call `Connections.sweep(now)` with a chosen `now`.
   Converting the timeout tests to driven sweeps removes most of the wall
   time and the flake risk in one move.
2. **No hang protection.** No `pytest-timeout`; nine unguarded
   `await reader.read()` calls (`test_protocol.py:777,900,993`,
   `test_hardening.py:624,2116`, `test_server.py:267,317,364`,
   `test_headers_writer.py:586`). A regression that stops the server from
   closing becomes a CI job that runs to the GitHub limit.
3. **Environment-coupled hard failures.** `test_compression.py:178-186`
   asserts the linked Brotli version (fails on any distro Brotli 1.1.0);
   `test_h2.py:59-97` shells out to `curl` and `openssl` without a skip.
   Skip with a clear reason instead of failing. `tests/cython/conftest.py`
   papers over an import cycle between `stario/__init__.py` and
   `stario_cython.exchange` that would otherwise make collection order
   matter.

Also: `tests/helpers.py:38-82` re-implements `text/json/html/redirect/empty`
and `test_writer.py:466-524` then tests that double's own rules (production
raises `StarioRuntime`, the double raises `RuntimeError`); duplicated
response readers, port helpers and H2 handshakes across `tests/cython/http.py`,
`test_server.py`, `test_serve.py`, `test_threads.py`, `test_h2.py`;
hypothesis has no fixed seed or profile in CI; `TestClient` runs with all
timeouts off, no backpressure, one protocol per request and cleartext only,
which is fine by design but should be stated in its docstring.

Coverage gaps worth closing: a client-sent GOAWAY (none), a multi-frame
CONTINUATION block and flood (the CVE that motivates bundling nghttp2),
RST_STREAM while a handler awaits `body()`, `serve()` with `config.ssl`,
multipart `max_fields`, a `Files` entry larger than `STREAM_SPAN`, the B1
tuple child, the B2 case rule, `expires=<str>`, the empty-message exception
export, `Relay` across real worker loops.

## 7. Status (2026-11-06)

Landed on this branch, with tests, all 1528 tests green:

- Bugs: B1, B2, B3, B4, B5, B7, B8, B9, B10, B11, B12 (a–d), B13 (confirmed
  and fixed; `test_h2_body_overflow_during_read_is_the_handler_413`). B6 is
  documented rather than changed, to stay consistent with `w.html(str)`.
- P1 telemetry hot path: lock taken directly, per-thread uuid7 state with
  pooled randomness, cheaper serialisation; `events` capped at 1000; the
  queue-full message is rate-limited. SQLite tracer and the TTY live
  footer stay.
- P2 markup (pure Python round): `Tag.__call__`, `classes`, `styles`
  fast paths, attribute-escape cache dropped. The render-shape change
  (step 4) and the compiled builder (step 11) are still open.
- P3 SSE and signals gates.
- B11 was adjusted after review: an empty file input counts toward
  `max_fields`, not `max_files`, and opens no spool.
- Compression: the Python compressor classes, duplicate Accept-Encoding
  parser, duplicate `merge_vary`, and `stario.http.wire` are gone;
  `filesystem` precompresses through `compress_bytes` on the Cython codecs.
